# Kensym 摄影作品集新增需求｜Vibe Coding Prompt

请在现有 Kensym® 个人作品集网站中，仅实现本文件描述的新增内容。先阅读现有 `program.md`、`src/main.jsx`、`src/capabilities.jsx`、`src/styles.css`、`worker/src/index.js` 与 `worker/wrangler.toml`，复用项目当前的 React、Vite、Lucide React 和 Cloudflare Worker/R2 技术栈。不要重写现有首页、能力页或既有视频播放逻辑，也不要擅自修改已有文案与作品数据。

## 目标

1. 在首页顶部导航现有“关于 / 作品 / 能力”之后新增第四个栏目“摄影”。
2. “摄影”链接到新的独立摄影作品集页面。
3. 摄影页提供分类筛选、缩略图浏览，以及点击后才加载高清图的沉浸式灯箱体验。
4. 照片只上传一份原图至 Cloudflare R2，由服务端动态生成、压缩和缓存展示所需的图片变体。
5. 摄影页在视觉上具有独立气质，但仍能明确看出属于 Kensym® 现有网站。

## 改动边界

- 只新增摄影入口、摄影独立页、摄影数据配置和对应的 Worker 图片服务。
- 首页除新增“摄影”导航链接外，不增加摄影内容板块。
- 摄影页采用与能力页相同的简化顶部导航：左侧 `Kensym®` Logo，右侧为带左箭头的“返回首页”。不要复制首页完整导航。
- 不提供下载按钮、原图链接、复制链接入口或任何主动下载渠道。
- 不将示例分类、示例作品名或占位器材信息当成用户的真实内容。

## 页面入口与代码组织

- 新增独立 HTML 入口，例如 `photography.html`。
- 新增独立 React 入口组件，例如 `src/photography.jsx`。
- 尽量复用现有主题变量、`.shell`、Logo、导航高度、字体和基础动效；摄影页专属样式使用清晰的命名空间，避免影响首页和能力页。
- 首页“摄影”链接使用明确的相对路径指向摄影页，并确保桌面导航与移动菜单中均可访问。
- 将摄影作品数据集中维护在一个清晰的数据清单中，不要把作品散落硬编码在 JSX 结构里。包含 R2 `objectKey` 的完整清单必须留在 Worker/R2 私有侧，浏览器只接收公开展示字段、不可推导对象路径的 `assetId` 和短时签名派生图地址。

## 内容与数据模型

分类尚未最终确定。开发阶段可以使用以下明确标注为 `DEMO / 待替换` 的示例分类：`全部 / 人像 / 风光 / 街头 / 纪实`。最终分类必须能通过数据配置直接替换，不需要调整页面结构或筛选逻辑。

每张照片的私有清单记录至少包含：

```js
{
  assetId: '稳定、唯一且不能用于推导 R2 路径的公开 ID',
  objectKey: 'R2 中的对象 key，不是公开原图 URL',
  title: '作品标题',
  category: '分类',
  year: '年份',
  camera: '机身信息',
  lens: '镜头信息，可留空',
  description: '简短描述，当前为可选字段',
  width: 0,
  height: 0,
  focalPoint: '可选的裁切焦点'
}
```

`width` 和 `height` 用于在图片加载前确定比例，避免布局跳动。Worker 对外返回数据前必须移除 `objectKey`，图片接口只接受 `assetId` 并在服务端解析实际对象。界面只在字段存在时显示镜头和简短描述，不渲染空标签。为私有清单加入醒目的替换说明，告知维护者只需替换分类和作品记录，以及上传对应的 R2 对象；不要在页面中放置大段使用教程。

## 视觉方向

延续现有 Kensym® 的品牌骨架：近黑底、暖白文字、Manrope/DM Sans、克制的荧光黄绿色强调、细分隔线、编辑感留白与低调的进入动画。摄影页不能只是首页作品卡片的复制版，应呈现更安静、偏画册和暗房阅片台的独立气质。

- 首屏保持紧凑，不制作营销式巨型 Hero。页面打开后第一屏必须能同时看到摄影页标题和首行缩略图线索。
- 页首使用 `PHOTOGRAPHY / 摄影` 作为明确标题，可辅以一句简短的中性占位说明，但必须标记为待替换文案。
- 强调色只用于当前筛选状态、焦点状态、细线或小型状态提示，不大面积铺色。
- 缩略图区域是页面主角。使用富有编辑节奏的响应式网格，兼容横图和竖图，但不要用导致阅读位置频繁跳跃的随机布局。
- 为尚未接入图片的条目设计显眼但克制的空图片板块：保持预设宽高比，显示编号、`IMAGE PENDING` 和对象 key 占位提示。它必须看起来是设计完成的内容槽位，而不是破损图片。
- 卡片圆角不超过 8px；避免嵌套卡片、装饰性渐变球和大面积单色装饰。
- 缩略图 hover 只做轻微放大或遮罩变化，同时出现标题、年份和“查看”提示；触屏设备不依赖 hover 才能获知关键信息。

## 分类筛选

- 分类栏放在标题区与缩略图网格之间，可在滚动时保持可用，但不得遮挡顶部导航或内容。
- 使用语义化按钮实现单选筛选，提供明确的当前状态、键盘焦点和 `aria-pressed`。
- 切换分类时保留平稳、短促的过渡，不重新加载页面。
- 筛选结果为空时显示设计完整的空状态，不显示破损网格。
- 移动端分类较多时允许横向滚动，并提供可发现的边缘线索；不能压缩成难以点击的小字。

## 缩略图加载策略

用户只向 R2 上传原图。网格绝不能直接请求原图：

1. Worker 根据网格容器宽度和设备像素比返回动态缩放后的缩略图。
2. 使用浏览器支持良好的现代格式，优先 AVIF/WebP 并提供可靠回退；按图片类型设置合理质量，而不是固定返回超高质量。
3. 使用 `srcset` 与 `sizes` 提供有限且明确的响应式宽度档位，防止生成无限组合的缓存变体。
4. 首屏少量缩略图可优先加载，其余使用原生懒加载；所有图片保留固定比例，避免 CLS。
5. Worker/CDN 为派生图设置长期缓存；原图更新时使用版本字段或对象版本改变 URL，避免粗暴禁用缓存。
6. 若当前 Cloudflare 套餐或运行环境尚未启用图片变换能力，保留清晰的适配层和配置说明，不允许回退成前端加载原图再用 CSS 缩小。

## 灯箱与高清图

- 点击缩略图后打开全屏灯箱，此时才请求适合当前视口的高清派生图；“高清”是经过服务端压缩、尺寸不超过实际显示需求的派生版本，不暴露 R2 原始对象。
- 灯箱采用深色全屏背景，照片占主要视觉空间，不能被装饰性卡片包裹。
- 显示作品标题、年份、机身、可选镜头和可选简短描述。
- 提供熟悉的图标按钮：关闭、上一张、下一张；使用 Lucide 图标并提供 tooltip 与无障碍名称。
- 支持键盘 `Esc` 关闭、左右方向键切换；点击遮罩可关闭，但点击照片和信息区不能误关闭。
- 上一张/下一张严格遵循当前筛选结果；切换至边界时按循环浏览处理，并让屏幕阅读器获得当前序号信息。
- 打开灯箱后锁定背景滚动，关闭后恢复原滚动位置，并将焦点送回触发灯箱的缩略图。
- 当前高清图完成后，只预取相邻一张的“视口级派生图”，不要预取原图或整个相册。
- 提供加载中、加载失败与重试状态。切换图片时避免上一张短暂冒充下一张。
- 不显示下载图标或原图入口；可阻止图片上下文菜单和拖拽，作为轻度界面约束，但不得把它描述成可靠的防保存措施。

## Cloudflare R2 与 Worker 图片链路

继续使用现有 Worker 域名 `https://kensym15.dpdns.org`，新增 `/photo/...` 路由。新 R2 bucket 的 Worker binding 名确定为小写 `photo`，不得替换或复用现有视频 bucket binding。

设计清晰、可维护的接口，例如：

- 摄影清单或签名派生图地址接口：`/photo/manifest`
- 派生图片接口：`/photo/image/:assetId`

路径可以按现有 Worker 结构调整，但前端不得持有 R2 公共地址或 `objectKey`，R2 bucket 不得设为公开。原始对象只允许 Worker binding 读取，不建立可直接访问的原图路由。私有清单可存放在 R2 的保留对象中或 Worker 可读取的服务端配置中，但不得被静态打包进浏览器代码；公开 manifest 只能输出展示字段、`assetId` 和短时派生图信息。

### 防盗链与短时签名

必须同时实现来源校验和短时签名：

1. 对 `/photo/...` 请求校验 `Referer`：拒绝空值、解析失败值和非本站来源，仅允许配置白名单内的正式站点来源与明确启用的本地开发来源。
2. 同时校验 `Origin`（存在时）并配置严格 CORS；不得返回通配符 `*`。
3. 图片 URL 携带短时有效的 `exp` 和 `sig`。签名在 Worker 中使用 secret 和 HMAC 生成，至少覆盖 `assetId`、允许的变体参数、过期时间与版本；验证签名后才在服务端将 `assetId` 解析为对象 key，并使用恒定时间比较验证签名。
4. 签名 secret 通过 Worker secret 注入，不写入仓库、前端代码、查询接口响应或 `wrangler.toml` 明文。
5. 过期、篡改、越权尺寸、未知 `assetId` 和非法路径均返回合适的 4xx，不泄露 bucket 结构、对象 key 或内部异常。
6. 规范化并白名单化图片变体参数，只允许预设的宽度、质量、格式和 fit 模式，防止任意参数造成缓存爆炸或资源滥用。
7. 防止路径穿越和资源 ID 批量枚举；`assetId` 应不可连续猜测，对清单与图片接口增加合理限速，并保留 Cloudflare WAF/Rate Limiting 的部署配置说明。
8. 签名 URL 的有效期应足够覆盖正常浏览，但不能作为长期链接复用；缓存键与签名策略要协调，既不让过期签名绕过鉴权，也不重复缓存相同派生图。
9. 响应使用 `Content-Disposition: inline`、准确的 `Content-Type`、`X-Content-Type-Options: nosniff` 和合理的 CSP/跨源资源策略。
10. 日志不得记录签名 secret；对完整签名查询串进行脱敏。

不要声称这些措施能彻底阻止用户保存已经在浏览器中成功显示的图片。目标是阻止空 Referer 请求、外站盗链、URL 长期复用、公开枚举和原图直接访问，同时不提供主动下载渠道。

## 响应式与无障碍

- 在大屏、常规笔记本、平板和手机上分别设计稳定的网格列数与间距；不要通过视口宽度连续缩放字号。
- 横竖图必须完整、专业地呈现，缩略图允许经过配置的裁切，灯箱默认完整显示，不裁掉主体。
- 图标按钮具有至少 44px 的触控区域。所有可操作元素具备可见焦点，颜色对比符合 WCAG AA。
- 尊重 `prefers-reduced-motion`，关闭非必要位移和缩放动画。
- 图片 `alt` 使用作品标题或数据中的独立替代文本；纯占位槽使用合适的状态文本，不伪装成真实作品。
- 页面在无 JavaScript 或接口失败时至少显示明确错误说明，不留下空白主区域。

## 验收标准

1. 首页桌面与移动导航均出现“摄影”，且能进入摄影独立页；现有三个导航入口行为不变。
2. 摄影页使用简化的 Logo +“返回首页”导航，并与能力页交互一致。
3. 示例分类被明确标记为待替换；分类切换、空状态和灯箱内的当前筛选顺序正确。
4. 网格初次浏览的网络请求中不存在 R2 原图，只包含合适尺寸的压缩缩略图。
5. 只有点击缩略图后才请求当前视口所需的高清派生图，并最多预取相邻图片。
6. 灯箱支持按钮、遮罩、Esc、方向键、焦点恢复、加载错误与移动端手势友好的控件。
7. 空 Referer、外站 Referer、过期签名、篡改尺寸、未知 `assetId` 和非法路径均无法获得图片。
8. 页面源码、网络响应与前端包中没有 R2 公共地址、原图直链或签名 secret。
9. 不出现下载按钮或原图入口，图片响应为 inline；文档准确说明无法绝对阻止截屏或保存已显示内容。
10. 构建成功，现有首页、视频弹窗与能力页无回归；对 Worker 签名验证和参数白名单至少添加关键路径测试。
11. 使用真实浏览器分别检查桌面和移动视口，确认首屏能看到标题及首行作品线索、文字无溢出、控件无重叠、图片比例稳定。
